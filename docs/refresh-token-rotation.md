# Refresh Token 회전과 기기별 로그아웃

기존 원자적 회전은 `2c72f0a`로 로컬 `develop`에 반영했다. 추가 family 폐기와 HTTP 보완은 `feat/auth-session-family`에 구현했다.

## 동작과 정책

같은 RT의 동시 갱신은 하나만 성공하며 나머지는 401이다. 중복 요청 자체를 이유로 승자의 후속 RT를 폐기하지 않는다. `rotate-refresh-token.lua`는 구 RT·소유자·family·전역 버전과 폐기 표식을 확인하고, 후속 RT 저장·구 RT 소비·사용자 인덱스 변경을 하나의 Redis 실행에서 확정한다.

단일 기기 로그아웃은 **로그인별 family 전체**를 폐기한다. 서명·종류·소유자를 검증한 RT이면 이미 소비된 과거 RT로도 해당 family의 최신 후속 RT를 폐기할 수 있다. `revoke-refresh-family.lua`가 사용자 인덱스에서 해당 family만 찾아 삭제하고 폐기 표식을 함께 기록한다. 다른 기기의 family와 새 로그인은 유지된다. family 없는 레거시 RT는 기존의 제출 토큰 삭제 동작을 유지한다.

회전이 먼저 확정되면 로그아웃이 그 후속 RT를 삭제한다. 로그아웃이 먼저 확정되면 회전과 일반 저장 스크립트가 폐기 표식을 보고 거절한다. 표식 TTL은 제출 RT, 이미 존재하는 표식, 해당 family의 활성 후속 RT 가운데 가장 긴 남은 TTL 이상이다. TTL 없는 비정상 데이터가 발견되면 표식을 영구 유지해 재활성화를 막는다. 정상 토큰에서는 만료에 따라 표식도 정리된다.

로그아웃에 제출한 AT만 즉시 블랙리스트에 넣는다. 제출하지 않은 기존 AT는 만료까지 유효할 수 있다. 이는 확정한 A 정책이다. 전체 로그아웃은 전역 버전을 증가시켜 기존 AT와 RT를 차단한다. `/api/auth/logout/all/{userId}`는 Bearer 인증과 본인 ID 일치를 요구한다. 인증 누락은 401, 다른 사용자 ID는 403이다. 인증 오류의 `WWW-Authenticate` 헤더에는 ASCII만 사용하고 한국어 설명은 UTF-8 응답 본문으로 제공한다.

일반 RT 저장은 `save-refresh-token.lua`에서 family 표식과 전역 버전을 확인한 뒤 메타·해시·인덱스를 함께 쓴다. 저장 오류나 실행 결과 불명은 성공한 토큰으로 반환하지 않는다. Lua는 격리 실행을 제공하지만 임의의 실행 중 오류를 롤백하지 않으므로 키 타입·TTL·상태 검증은 쓰기 전에 수행한다.

## 검증

```bash
./gradlew test --tests com.example.jammoney.auth.RefreshTokenRotationIntegrationTest
```

기본은 Testcontainers의 전용 Redis를 사용한다. CI가 이미 격리한 Redis를 제공한다면 `RT_TEST_REDIS_HOST`와 선택적인 `RT_TEST_REDIS_PORT`를 지정할 수 있다. 이 테스트는 자신의 사용자 키를 생성·삭제한다.

프로젝트 회귀 테스트 45회와 기존 예비 하네스 3개 메서드가 통과했다(JUnit 집계 48건). 정상 회전·동시 소비·TTL·버전·저장 오류와 함께 과거 RT의 family 폐기, 다른 기기 유지, 재저장 차단, 가장 긴 후속 TTL, 로그아웃/회전 경합, 검증 직후 로그아웃을 확인했다.

별도 HTTPS 하네스는 실제 제품 컨트롤러·필터·서비스·저장소, MySQL과 Redis를 연결한다. 회원가입·로그인·쿠키 자동 갱신·갱신 경합·단일/전체 로그아웃·보호 경로 접근을 검증하고 개선 전후 비용도 측정한다. 실행 명령과 수치, 실패 시도 원본은 [인증 HTTP 실험](../../experiments/auth-http/README.md)과 [결과](../../experiments/auth-http/RESULTS.md)에 기록한다.

## 적용 범위와 비용

기기별 로그아웃은 사용자 인덱스 전체를 읽으므로 인덱스 항목 수에 비례한다. 현재는 별도 family 인덱스가 없는 기존 데이터도 처리하는 방식을 선택했다. 만료된 토큰의 인덱스 잔여 항목도 순회 비용에 포함될 수 있다. 활성 기기가 1·5·20개인 측정으로 장기간 누적된 거대 인덱스의 비용을 보장할 수 없다.

Standalone Redis 대상이다. Redis Cluster의 hash slot·동적 키 접근, 장애조치 내구성, 응답 유실·모든 장애 조합은 미검증이다. HTTP 하네스는 인증 경로를 실제 서버로 실행하지만 앱 전체·외부 API·프런트엔드 브라우저 실행을 포함하지 않는다. 절대 운영 SLO와 최대 처리량도 이번 비교의 판정 대상이 아니다.
